# Ticket Types & Priority

Not all tickets are created equal. The Helpdesk must accurately categorize tickets to ensure critical business functions are restored first.

## 1. Incident vs. Service Request (ITIL Definitions)
- **Incident:** An unplanned interruption to an IT service or reduction in the quality of an IT service. (e.g., *"My laptop won't turn on"*, *"The CRM is throwing a 500 Error"*). **Goal: Fix what is broken.**
- **Service Request:** A formal request from a user for something to be provided. (e.g., *"I need a new mouse"*, *"Please install Adobe Acrobat"*, *"Create a new user account"*). **Goal: Fulfill a standard need.**

## 2. Priority Matrix for Daily Support
*(For Major Incidents, refer to the [Incident Management Guide](../../incidents/Incident-Management-Guide/severity.md)).*

For standard Helpdesk operations, use this matrix:

| Priority | Description | Example |
| :--- | :--- | :--- |
| **P1 - Critical** | Entire site or critical system down. | Factory floor Wi-Fi is completely offline. |
| **P2 - High** | Urgent issue for a VIP or a blocker for a small team. | The CEO cannot access their email. |
| **P3 - Normal** | Standard incident or request. User can still work, or workaround exists. | User needs a password reset; printer is jammed. |
| **P4 - Low** | Informational, cosmetic, or scheduled tasks. | Requesting a software upgrade for next month. |

## 3. VIP Handling
Users tagged as **VIP** (Very Important Person - e.g., C-Level Executives, VP of Sales) automatically have their tickets bumped up one priority level. Their downtime costs the company significantly more money per minute than standard users.
